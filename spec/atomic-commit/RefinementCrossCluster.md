# Refinement note: cross-cluster TLA+ spec to code

This note maps [`AtomicCommitCrossCluster.tla`](AtomicCommitCrossCluster.tla)
to the Orleans.Lattice code that replicates an atomic-write saga to a peer
cluster and keeps it all-or-nothing visible there, so the abstract model and the
runtime artefact are traceably the same protocol. Like
[`Refinement.md`](Refinement.md), the single-cluster note it complements, it is
a **documented mapping, not a machine-checked refinement proof**.

Its scope is the **receiver**. The origin's saga is
[`AtomicCommit.tla`](AtomicCommit.tla)'s, instanced unchanged, and its own
properties are checked and mapped there. Nothing below re-maps the origin's
protocol steps; the origin rows map only what each origin step writes for
replication. Coverage of one half must not be read as coverage of the other
(issue #2324).

## Variable mapping

| Spec variable | Protocol role | Code counterpart |
|---------------|---------------|------------------|
| `phase`, `vote`, `decision`, `terminal`, `pend`, `orphanDone`, `forgotten`, `masked`, `revision` | The origin saga and its registry | `AtomicCommit.tla`'s variables, mapped in [`Refinement.md`](Refinement.md). Only saga `t1` moves here; `t2` stays in `init`. |
| `xtree` | Shape of the replicated saga | Whether the saga's terminals carry `WalRecord.CrossTreeOperationId` (a `LatticeCrossTreeTxGrain` sub-saga) or not (a single-tree `AtomicWriteGrain` saga). Fixed per behaviour. |
| `oext[tr]` | Authoring-side delegation | The origin tree's `TxRegistryState.ExternalAuthorities` row for the saga, written by `TxRegistryGrain.RegisterExternalDecisionAuthorityAsync` and dropped when the sub-saga's finalize records the decision locally. |
| `orcv[tr]` | Receiving-side delegation on the origin | The origin tree's `TxRegistryState.ReceiverDecisionAuthorities` row. Only the public apply seam handed the origin's own terminal could write one, and the registry refuses it. |
| `outbox` | Unacknowledged replication records | The origin's WAL records past the shipper's durable per-partition cursor for this peer (`ReplicationShipperGrain`): every record is re-shipped until the receiver acknowledges it. While the peer is off the log the shipper withholds its saga records, which stay here. |
| `dlv` | Delivery history | The prepares the receiver has applied at least once. Modelling device for stating the ordering assumption; no production counterpart. |
| `rconn` | Receiver attached to the stream | A receiver in live incremental replication, as opposed to one that will join through a snapshot bootstrap. |
| `rpend[k]` | Receiver leaf's prepared bucket | The receiver leaf's pending-tx bucket for the saga, installed by `IReplicationApplyGrain.ApplyPreparedSetAsync`. |
| `rterm[k]` | Receiver leaf's applied terminal | The receiver leaf's recently-terminal memory (`BPlusLeafGrain.ApplyTxCommit` records it even with no bucket); the late-prepare refusal's and the orphan guard's input. |
| `rproj[k]` | Receiver leaf's materialised projection | Whether the receiver leaf's committed rows hold the saga's write. |
| `rarr[tr]`, `rexp[tr]` | Receiver tally | `TxRegistryState.TerminalArrivals` and `TxRegistryState.ExpectedTerminals` on the receiver tree's registry. `rexp = 0` stands for "no entry". |
| `rdec[tr]` | Receiver registry's local decision | `TxRegistryState.Decisions` on the receiver tree's registry. |
| `rout[tr]`, `rstage[tr]` | Cross-tree hand-off progress | The outcome and position of `LatticeGrain.ApplyTxTerminalAsync`'s barrier hand-off after the tree's tally completes: register the delegation, then notify the barrier. |
| `rdeleg[tr]` | Receiver delegation to the barrier | The receiver tree's `TxRegistryState.ReceiverDecisionAuthorities` row, written by `TxRegistryGrain.RegisterReceiverDecisionAuthorityAsync`. |
| `rdial[tr]` | Barrier unreachable | A failing grain call from `TxRegistryGrain.ResolveReceiverDelegatedAsync` to the barrier. |
| `carr[tr]`, `cdec` | Barrier state | `CrossTreeReceiverState.Arrived`, and `CrossTreeReceiverState.Decided` with `CrossTreeReceiverState.Committed`, published by `LatticeCrossTreeReceiverGrain.GetDecisionAsync` once durable. |
| `rfin`, `rtodo` | Owed receiver work | Trees the barrier's decided notify told to finalize, and leaves owed the terminal by a finalized registry. Production carries both inside the apply call and re-drives them through redelivery; the model keeps them as durable obligations. |
| `gone` | The record a shipper gap lost | A record a `WalRetention` trim passed before the shipper read it (issue #4534), or a batch the shipper could not encode, quarantined in `ReplicationShipperState.EncodeQuarantineFrom` and `ReplicationShipperState.EncodeQuarantineThrough` (#4651). Neither is ever shipped to the peer again. |
| `purged` | The origin's decision row is gone | The forgotten saga's decision purged from the origin tree's registry: the second of the two absences the replay filter reads. |
| `ptrim` | The origin WAL holds no prepare of the saga | `LatticeWalGc` has trimmed past every prepare of the saga, which is what `TxRegistryGrain.IsWalPurgeCleared` waits for. |
| `rs` | The peer's re-seed | `none`: on the log. `marked`: off the log, with `ReplicationShipperState.ReseedRequiredEpoch` set, saga records withheld, `ReplicationShipperState.ReseedRetainFrom` capping the published read positions and the replay hold taken. `drained`: the receiver has drained an export opened after the marker while every silo honoured the hold, and the shipper has not yet rewound. |
| `detached` | The peer's shipper is off the topology | `ReplicationShipperState.DetachedFromLog`. |
| `rpoison` | The receiver poisoned the saga | The saga's txid in the receiver tree's `IReceiverSagaPoisonGrain` set, with the re-seed it owes. |
| `losses` | Loss budget | Modelling bound: at most one loss path per behaviour. No production counterpart. |
| `preguard` | A silo predates the purge hold | `PurgeHoldSupport.AllSilosHonour` is false: some active silo hosts no `IWalPurgeHoldGrain`, so its registry predates #4553's guard and the hold, and purges on retention alone. |
| `filt`, `verdict` | The replay filter | `ReplicationShipperState.ReplayFilterHorizon` set by a bootstrap or a re-seed rewind, and the verdict the shipper took for the saga at first sight and keeps for the rest of the replay. |
| `afence`, `bfence` | An imported tree's read fence | The drain's durable read fence on the receiver tree (#4594), which a cross-tree import holds past the drain (`BootstrapCoordinatorState`, #4706, the fix for issue #4683) until no barrier indexed under the tree is undecided and every sibling tree has passed its boundary (#4716 and #4721, the fix for issue #4684). |
| `uimp[tr]` | A bare import's uniform-arrival mark | Issue #4684's R2 (#4716): the drained import's export epoch per receiver tree and origin, and the operations its rows name, recorded in the tree's barrier index; a barrier takes the tree's arrival with its siblings' verdict when that epoch is past the operation's decision stamp for the tree (`ReplicationCrossTreeDecisionStamper.StampAsync`) and the import named nothing of it. |
| `ubnd`, `abnd`, `acaught`, `bcaught` | R1's boundary | Issue #4684's R1 (#4721): each sibling tree's log and per-partition tails, captured at the end of the tree's export (`CrossTreeExportGate.CaptureSiblingBoundariesAsync`, `CrossTreeSiblingBoundary`), and passed once the sibling's shipper vouches acknowledged positions on that log at or past them (`ReplicationAckedPositions`), or once the sibling has been drained here from an export opened after the capture (`ILatticeBootstrapCoordinatorGrain.GetDrainedExportEpochAsync`; `acaught`, `bcaught`). The model's capture is at the boundary; production's, at every export's end, is later and so covers more. A shipper off the log advances no frontier, so its tree passes only the second way. |
| `decom`, `afresh` | A tree removed for good, then added back fresh | A decommission of the peer: the origin releases its cross-tree holds (not implemented, issue #4723) and the receiver drops the tree from every undecided barrier (`ILatticeCrossTreeReceiverGrain.NotifyParticipantAbsentAsync`, #4698). Added back, the tree is a fresh replica, unreadable until its full bootstrap, which clears its stale buckets (#4701). |
| `xo`, `xs` | The export of a cross-tree import of tree A | `xo`: the export is open, and whether the operation was decided at the origin when it opened - the open epoch C0 that issue #4684's R2 compares with the operation's decision stamp (#4716). `xs`: what the export closed with, its decision read and rows of one instant (`LatticeSnapshotProvider.EnumerateCompletionAsync`, #4694, the fix for issue #4685), and `cut`, tree A's records retained at the close, which the shipper may re-ship. |
| `boff`, `bpur` | Tree B off the log; tree B's decision row purged | `rs` and `purged` for tree B, on the loss path that takes both trees off the log at one boundary. |

## The Detector column

The rules are [`Refinement.md`'s](Refinement.md#the-detector-column): a detector
is a test over production code, never a TLA+ mutation; the names are resolved by
`RefinementDetectorMappingTests`; and no census of the column is recorded here.
Every detector named above was shown to go red by perturbing the production code
it covers; the perturbations are listed in the pull request that last changed
each citation. Where a detector goes red only with a second production mechanism
also neutralised - the settle, or the receiver's apply cache - the row says so.
The gap-citation gate checks that a row reporting a gap cites an issue, not that
the issue is still open, so a fixed defect is recorded in prose as fixed by its
pull request, which the gate cannot tell from an open one.

## Deliberate abstraction gaps

- **The origin is one saga.** `AtomicCommit`'s second saga never starts, so
  inter-saga last-writer-wins on a shared key is not exercised on the receiver
  either. That is the single-cluster note's per-saga-projection gap, unchanged.
- **One source shard per key, and the same layout on both clusters.** Production
  tallies source-shard indices independently of the receiver's layout and fans
  each observed index out through its split-forward closure
  (`TerminalFanOutResolver`); the model identifies a shard with a key, so a
  receiver whose shards have split since is not modelled.
- **Unstamped terminals.** The model's terminals all carry the touched-shard
  count. Production writes a count of 0 on every terminal outside the saga
  coordinator's broadcast, including the split's retroactive-sweep terminals, and
  the receiver takes them down the legacy path; for a multi-shard saga that marks
  the saga early (`RAllOrNothingLegacyNoTallyMultiShard`). That is harmless
  once every prepare of the saga has arrived, which the shipper's terminal hold
  now guarantees for every terminal, unstamped ones included: checked in TLC by
  tightening `DeliverTerminal`'s guard to that saga-wide form, under which
  `RAllOrNothing` holds with every terminal unstamped. The base keeps the
  weaker per-shard guard as the minimum contract, so the mutation still fires.
- **The bootstrap and the re-seed export.** Taken atomically at the drain for a single-tree saga and for the re-seeds of the path that takes both trees off the log, on which the saga is finished and every purge precedes the boundary, so nothing interleaves with the export. A cross-tree import of tree A takes it in three steps - open, close, drain - so the operation can prepare, decide, purge and arrive at the barrier between them; the close is one instant. Production's export is two passes against a frozen
  snap0, and its late-decision pass ships a decision row for any saga it
  carried that decided while it ran (issue #4627), and its completion from the
  source WAL ships whole any saga that decided between its passes (issue #4685,
  fixed by #4694), so its decision read and its rows are of one instant, as the
  model's are. Its drain applies the rows one at
  a time behind a read fence for the whole drain (issue #4526, fixed by #4594),
  which is observationally the model's atomic import, and nothing of the saga
  reaches the receiver between a re-seed's export and its drain: the sender
  withholds and the receiver refuses stragglers. A stranded origin bucket whose
  decision row has already been purged is exported as the split the origin
  itself serves (#2318's premise): the base reaches no stranded origin bucket,
  for the reason `AtomicCommit`'s base does not, and the stranding half of
  `RAllOrNothingExportOverStrandedPrepare` alone reaches that split through
  the purged answer. The base exports a decided saga's still-resident buckets
  as committed rows; that is what keeps the settle atomic, and without it a
  reader between two prepare arrivals sees the saga split
  (`RAllOrNothingSettleKeyByKey`).
- **The origin WAL is derived, and the GC is coarse.** The model keeps no WAL
  of its own: what the origin has appended follows from the saga's state, and
  what it still retains is that minus a record a shipper gap lost and, once the
  GC has trimmed them, the saga's prepares. The GC's trim of the prepares is
  taken together with the guarded purge that waits for it, and the model never
  trims an acknowledged terminal, so a rewind re-ships it; the registry already
  counted it, so the re-ship is a duplicate the tally absorbs.
- **Loss paths, one per behaviour.** The transport never loses a record by
  itself. Each way production loses one is an action with its fix: a shipper
  gap (a `WalRetention` trim or an encode failure), a detach and re-add, a
  receiver poison, and a decommission and fresh re-add. A behaviour takes at
  most one, in either shape, on tree A's stream while tree B stays on its own;
  the two trees are symmetric there, so fixing which one is lost loses nothing.
  One more path takes both trees off the log at one boundary (`MutualOffLog`),
  the case a peer added to a cluster with trimmed logs is in, and re-seeds each
  (`TreeReseed`). A second loss while the peer is already off the log raises
  the marker in production
  (`ReplicationShipperGrainTests.A_second_encode_failure_raises_the_marker_so_an_export_opened_past_the_old_epoch_does_not_clear_it`),
  which the model's single loss does not reach.
- **The instance is checked in slices.** Every cross-tree slice takes the export in steps (`SplitExport`). The base cfg checks every property
  with no loss path and a receiver that follows the stream, over both shapes; a
  receiver that joins through a bootstrap is checked in the `Join` variants. Each
  loss path is checked, with every property, in variant configurations that
  slice its instance so that every run fits the TLC budget. The single-tree
  slices partition it by how the receiver joins and by the saga's outcome. The
  cross-tree slices pair the bounds that interact rather than crossing all of
  them: a shipper gap and a receiver poison are checked with a silo that
  predates the purge hold, with no dial fault and no lost acknowledgement, and
  separately with dial faults and lost acknowledgements where every silo
  honours the hold; a detach and a decommission are checked where every silo
  honours the hold, since a silo that predates it holds nothing for either to
  release. A dial fault only hides a delegated key, and is checked with no loss
  path and on the gap's and the poison's follow slices; a lost acknowledgement
  only repeats a delivery, and is checked on every slice but the pre-hold ones,
  the decommission's join slice and the path that takes both trees off the log.
  What the pairing leaves out is either of them combined with a pre-hold purge
  on one behaviour, and a dial fault combined with a detach, a decommission or
  a joining receiver's loss. An
  aborting saga takes one vote set (no participant acking): which participant
  refused is invisible to the receiver, and the origin aborts the same way
  whichever it was. A silo that predates the purge hold is present from the
  start until `UpgradeDone`; starting with one loses nothing, since that step
  may come first. The path that takes both trees off the log is sliced by the
  decision rows a pre-hold silo purged before the boundary - none, tree A's, or
  both, tree A being the one purged by the trees' symmetry, and tree A
  re-seeded first when neither is - with the origin's saga finished and
  forgotten before the boundary, which every purge already requires. Its slices
  take no lost acknowledgement (`AckLoss`), because the rewind re-ships every
  retained record and so duplicates every delivery made before the loss; the
  other paths check the transport's own duplicates.
- **Mechanisms the model shows to be defence in depth.** Four production
  mechanisms are modelled but are not load-bearing in it, because another fix
  already covers the case: the purge guard behind the replay filter, the
  receiver poison's registry guard behind the tally, the poison re-seed's
  discard of a saga it did not carry behind that saga's withheld terminals, and
  the rewind's own wait for a pre-hold silo behind the drain's. Each is still
  pinned by its production detector, on the row of the action it guards.
- **The origin drives only part of `AtomicCommit`.** `PrepareTx`, `DecideTx`,
  `BroadcastStep` and `ForgetDecision` run for the replicated saga;
  `ShadowForwardOrphan`, `OrphanDrain` and `RegistryMask` never do. So no
  forwarded prepare on a split destination (which production writes to the
  destination's WAL and replicates), no orphan-drain terminal, and no masked
  registry view reaches the origin WAL or the export. A masked view would
  have exported as Indeterminate before #4501; the base's export reads the
  stored verdict, as production now does.
- **Key filters.** The shipper drops prepares outside a peer's `KeyFilter` or
  `KeyPrefixes` but always ships terminals, so on a filtered peer a saga is
  applied with its unreplicated keys absent, and `RAllOrNothing` holds only over
  the keys the peer replicates. The model replicates every key.
- **The receiver registry is never masked by retention.** No receiver-side
  `ForgetAsync` runs, so a receiver decision row is never tombstoned; the only
  `Indeterminate` a receiver registry gives is the failed dial.
- **No crash, reactivation or redelivery mechanics.** Production re-drives a
  partially applied terminal by redelivery; the model holds the owed work as
  durable obligations. A receiver leaf's recently-terminal memory is per
  activation, but since #4461 its late-prepare refusal also consults the
  registry's decision (issue #4445's fix), and on the replication path the
  settle stands in front of it. A reactivation is not modelled.
- **No snapshot read path as such.** The model has one read view, the point
  path's. Since #4461 the snapshot read paths give the same answer for an
  undiallable delegation (issue #4448); `RAllOrNothingSnapshotReadsUnresolvableAsInFlight`
  is the regression check.
